# persian-ticket-triage

دسته‌بندی و اولویت‌بندی خودکار تیکت‌های پشتیبانی فارسی، با رویکرد **مبتنی بر قواعد** (Rule-based)، بدون هیچ وابستگی خارجی.

![Dependencies](https://img.shields.io/badge/dependencies-none-brightgreen)
![Tests](https://img.shields.io/badge/tests-pytest-informational)

## این پروژه چه می‌کند؟

یک فایل JSONL از تیکت‌ها می‌گیرد و برای هر تیکت این‌ها را تولید می‌کند:

- **دسته**: `billing` (مالی) ، `technical` (فنی) ، `account` (حساب کاربری) یا `general` (عمومی)
- **فوریت**: `high` ، `medium` یا `low`
- **خلاصه**: حداکثر ۱۲ واژه
- **اقدام پیشنهادی**: صف مربوطه و کاری که اپراتور باید انجام دهد
- **میزان اطمینان** و **شواهد**: اینکه سیستم چرا این تصمیم را گرفته (قابل‌ردیابی و شفاف)

خروجی در یک فایل CSV ذخیره می‌شود که مستقیم در Excel با فارسی درست باز می‌شود.

## جریان کار

```
JSONL → خواندن امن → نرمال‌سازی → دسته‌بندی → فوریت → خلاصه → اقدام → CSV
```

## نصب و اجرا

فقط به Python 3.9 یا بالاتر نیاز دارید. چیزی برای نصب نیست.

```bash
git https://github.com/Ali-salek/persian-ticket-triage.git
cd persian-ticket-triage
```

### ۱) اجرای تیکت‌های نمونه

```bash
python ticket_triage.py
```

### ۲) پردازش فایل خودتان

```bash
python ticket_triage.py --input tickets.jsonl --output report.csv
```

### ۳) پردازش یک متن تکی

```bash
python ticket_triage.py --text "رمز عبورم کار نمی‌کند و حسابم قفل شده"
```

```
id        : CLI
category  : account
urgency   : medium
summary   : رمز عبورم کار نمی‌کند و حسابم قفل شده
action    : صف حساب کاربری: کمک به بازیابی رمز یا رفع قفل حساب
confidence: 0.77
evidence  : account=10 [رمز عبور:5, حساب:2, قفل:3] | technical=3 [کار نمیکند:3] | دلیل: دستهٔ برنده | فوریت=1 [قفل:1]
```

## فرمت ورودی

هر خط یک شیء JSON است. فقط فیلد `text` الزامی است؛ اگر `id` نباشد خودکار ساخته می‌شود (`line-<شماره خط>`).

```jsonl
{"id": "T-101", "text": "پرداخت انجام شد اما سفارش ثبت نشده، فوری بررسی کنید"}
{"id": "T-102", "text": "دوبار کسر شده از حسابم"}
```

خط خراب، غیر شیء، یا بدون `text` معتبر فقط یک **هشدار** چاپ می‌کند و پردازش ادامه پیدا می‌کند.

## خروجی نمونه

```
[high  ] T-101    billing    (اطمینان 0.83)  پرداخت انجام شد اما سفارش ثبت نشده، فوری بررسی کنید
[high  ] T-102    billing    (اطمینان 0.75)  دوبار کسر شده از حسابم، لطفاً پیگیری کنید
[high  ] T-104    technical  (اطمینان 1.00)  سایت قطع شده و هیچ صفحه‌ای باز نمی‌شود، همین الان رفع کنید
[medium] T-103    account    (اطمینان 0.77)  رمز عبورم کار نمی‌کند و حسابم قفل شده
[low   ] T-106    general    (اطمینان 0.50)  سلام، یک سؤال داشتم
...
```

نتیجه‌ها بر اساس فوریت مرتب می‌شوند (فوری‌ها اول).

ستون‌های فایل CSV:

| ستون | توضیح |
|------|-------|
| `id` | شناسهٔ تیکت |
| `category` | دسته |
| `urgency` | میزان فوریت |
| `summary` | خلاصهٔ حداکثر ۱۲ واژه‌ای |
| `action` | صف و اقدام پیشنهادی |
| `confidence` | میزان اطمینان (۰ تا ۱) |
| `evidence` | کلیدواژه‌ها و امتیازهایی که به این تصمیم رسیدند |

## چطور کار می‌کند؟

**نرمال‌سازی متن فارسی.** حروف عربی (`ي`، `ك`) به فارسی تبدیل می‌شوند، ارقام فارسی و عربی به انگلیسی، اعراب و کشیده حذف می‌شوند و نیم‌فاصله یکدست می‌شود. به همین دلیل «نمی‌شود»، «نمیشود» و «نمی شود» یکسان دیده می‌شوند.

**کلیدواژه‌های وزن‌دار.** هر دسته مجموعه‌ای از عبارت‌ها با وزن دارد. عبارت مشخص‌تر وزن بیشتری می‌گیرد (مثلاً «دوبار کسر» از «کسر» سنگین‌تر است).

**تطبیق دقیق.** «حساب» داخل «حسابداری» پیدا نمی‌شود ولی «حسابم» و «حساب‌ها» پیدا می‌شوند. عبارت‌های هم‌پوشان دوبار شمرده نمی‌شوند.

**ابهام یعنی `general`.** اگر امتیاز برنده کم باشد یا دو دستهٔ برتر تقریباً هم‌امتیاز باشند، تصمیم به انسان سپرده می‌شود.

**فوریت.** نشانه‌هایی مثل «فوری» و «قطع شده» امتیاز مثبت و عبارت‌هایی مثل «فوری نیست» امتیاز منفی دارند. دستهٔ `billing` یک امتیاز پایه می‌گیرد.

**امنیت CSV.** مقدارهایی که با `=` ، `+` ، `-` یا `@` شروع شوند با یک آپاستروف ایمن می‌شوند تا Excel آن‌ها را فرمول اجرا نکند (CSV injection).

## تنظیم رفتار

همهٔ «اعداد جادویی» و جدول‌ها بالای فایل `ticket_triage.py` جمع شده‌اند:

| ثابت | کار |
|------|-----|
| `MAX_SUMMARY_WORDS` | سقف واژه‌های خلاصه |
| `MIN_CATEGORY_SCORE` | حداقل امتیاز برای انتخاب یک دسته (وگرنه `general`) |
| `AMBIGUITY_MARGIN` | حداقل اختلاف دو دستهٔ برتر |
| `HIGH_URGENCY_SCORE` / `MEDIUM_URGENCY_SCORE` | آستانهٔ سطوح فوریت |
| `CATEGORY_KEYWORDS` | کلیدواژه‌ها و وزن هر دسته |
| `URGENCY_SIGNALS` | نشانه‌های فوریت |
| `ACTION_BY_CATEGORY_URGENCY` | اقدام پیشنهادی برای هر ترکیب دسته و فوریت |

کلیدواژه‌ها هنگام بارگذاری خودشان نرمال می‌شوند، پس لازم نیست نگران نیم‌فاصله یا `ي/ی` باشید.

## محدودیت‌ها

این یک نسخهٔ baseline است و معنا را «نمی‌فهمد»؛ فقط کلیدواژه می‌شمارد. نمونه‌اش:

- تیکت «پرداخت من با خطا مواجه شد و اپلیکیشن بسته شد» به‌خاطر وزن بیشتر کلیدواژه‌های فنی در دستهٔ `technical` می‌افتد، هرچند ممکن است مشکل پرداخت باشد.
- املای محاوره‌ای یا غلط‌های تایپی که در جدول کلیدواژه‌ها نیستند شناسایی نمی‌شوند.

## ایده‌های توسعه

- جایگزین‌کردن موتور قواعد با یک مدل زبانی (ساختار `Classification` برای همین منظور طراحی شده)
- ساخت مجموعهٔ ارزیابی برچسب‌خورده و محاسبهٔ دقت/بازیابی
- افزودن خروجی JSON و خواندن مستقیم از CSV
- ریشه‌یابی (stemming) بهتر برای فعل‌ها و پسوندهای فارسی
